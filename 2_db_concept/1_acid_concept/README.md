## Response Section

ความหมายของ ACID
    A-Atomicity(ความเป็นกลุ่มก้อนเดี่ยวกัน)
        ทุกคำสั่งใน 1 Transaction จะต้องทำงานสำเร็จ 'ทั้งหมด' หรือ 'ไม่สำเร็จทั้งหมด' ห้ามมีการบางอัน ทำงานได้บางอันทำงานไม่ได้ เช่น ถ้าระบบหักเงินผู้ซื้อไปแล้วแต่ยังไม่หักสินค้าใน stock แล้ว server ดับก่อนจะต้อง rollback ทั้งหมด

    C-Consistency(ความสอดคล้อง)
        การแก้ไขข้อมูลจะต้องเป้นไปตามข้อจำกัดที่ตั้งไว้ในระบบ ข้อมูลต้องไม่ขัดแย่งกันเช่น ถ้าบอกว่าเงินห้ามติดลบ transaction ที่พยามหักเงินจนติดลบ ฐานข้อมูลจะต้องปัดตกทันที

    I-Isolation(เป็นอิสระต่อกัน)
        ฐานข้อมูลจะต้องจัดการไม่ให้เกิด race condition โดยล็อกข้อมูลเพื่อจัดคิวให้ transaction แต่ละรายการเช่นเมื่อ A และ B กดจองที่นั่งตัวเดียวกันพร้อมกัน ฐานข้อมูลจะล็อกข้อมูลเพื่อให้ transaction ของ A เข้าไปเปลี่ยนสถานะที่นั่งได้ก่อน ส่วน transaction ของ B ที่เข้ามาระหว่างนั้นจะถูกปัดตกไป ส่งผลให้ในมุมมองของผู้ใช้ A จะได้ที่นั่งนั้นไป ส่วน B จะโดนระบบดีดออกเพื่อไปเลือกที่นั่งอื่นต่อไป

    D-Durability(ความคงทน)
        Transaction ที่ทำงานสำเร็จแล้วถ้าระบบล่มไปหรือไฟดับกลางทาง เปิดกลับมาข้อมูลจะยังต้องอยู่ครบเช่น ฐานข้อมูลจะต้องมี Transaction Log เพื่อบันทึกว่ามี transaction อะไรเข้ามาบ้าง(เขียนลง log เร็วกว่าไปแก้ table) เมื่อไฟดับแล้วเปิดเครื่องขึ้นมาใหม่ฐานข้อมูลจะได้ไปอ่านจาก log แล้ว redo transaction นั้นได้

ความรับผิดชอบ
    ฝั่งฐานข้อมูล
        I(Isolation) ทำหน้าที่ล็อกตารางเพื่อแยกไม่ให้แต่ละ transaction ชนกัน
        D(Durability) เขียน log ลงดิสเพื่อการันตีว่าข้อมูลจะไม่หายถ้าไฟดับ
        C(Consistency) ตรวจว่าข้อมูลที่ส่งมาถูกประเภทไหมเช่น data type, foreign key, unique key ตามที่ออกแบบไว้หรือปล่าว

    ฝั่งแอพ(backend)
        A(Atomicity) เขียนคำสั่งครอบ transaction เช่น บอกว่าจุดไหนเริ่ม(BEGIN TRANSACTION), จุดไหนจบ(COMMIT) หรือเมื่อเกิด error(ROLLBACK)
        C(Consistency) ฝั่งฐานข้อมูลจัดการได้แค่ข้อกำหนดง่ายๆตามด้านบนแต่ว่าในฝั่งแอพจะต้องมาจัดการทางฝั่ง business logic เพิ่มเช่น user คนนี้มีเงินพอไหม, มีสิทธ์เข้าถึงข้อมูลนี้หรือปล่าว
