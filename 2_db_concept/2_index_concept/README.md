## Response Section

ข้อดีของ Database Indexing
    1.ค้นหาข้อมูลได้เร็วขึ้นมาก(Fast Data Retrieval)
        - เหตุผลหลักๆในการใช้ index คือสำหรับตารางที่มีข้อมูลเป็นล้านๆ row การหาด้วย WHERE ใน column ที่มี index จะลดเวลาลงมาเยอะมาก

    2.เพิ่มประสิทธิภาพการเรียงลำดับข้อมูล(Efficient Sorting)
        - เมื่อเราใช้ ORDER BY กับ column ที่ทำ index ไว้ตัวฐานข้อมูลจะไม่ต้องเสียเวลาไปอ่านขาก table จริง
    
    3.ช่วยให้การเชื่อมตารางเร็วขึ้น(Faster JOIN Operations)
        - การ JOIN ระหวาง 2 ตารางขึ้นไป หาก column ที่เป็นตัวเชื่อม(เช่น Foreign Key)มีการทำ Index ไว้ระบบจะจับคู่ได้เร็วยิ่งขึ้น

    4.ลดภาระการทำงานของระบบ(Lower Resource Consumption)
        - เนื่องจากฐานข้อมูลไม่ต้องไล่อ่านข้อมูลจากทั้งดิสทำให้การใช้งาน CPI และการเขียนอ่านดิส(Disk I/O)ของ server ลดลงอย่างมาก

ข้อจำกัดและข้อควรระวัง
    1.เขียนข้อมูลช้าลง(Slower Writes: INSERT, UPDATE, DELETE)
        - ทุกครั้งที่เพิ่มข้อมูลใหม่หรือ แก้ของเก่าหรือลบข้อมูลออกตัวฐานข้อมูลไม่ได้ทำงานแต่ที่ตารางจริง แต่ต้องไปอัปเดตและจัดเรียงข้อมูลใน Index ใหม่ด้วย

    2.เปลื่องพื้นที่เก็บข้อมูล(Increased Storage Space)
        - ตัว Index ต้องใช้พื้อที่จัดเก็บข้อมูลจริงบนดิส ถ้าเราใช้งาน Index กับทุก column ขนาดของไฟล์ index จะใหญ่พอๆกันหรือใหญ่กว่าตารางจริง

    3.เพิ่มภาระในการบำรุงรักษา(Maintenance Overhead)
        - เมื่อมีการแก้ไขข้อมูลบ่อยๆ โครงสร้างของ Index อาจเกิดการกระจัดกระจาย(Fragmentation) ทำใหการหาข้อมูลจาก index ไม่เร็วเท่าเดิมคนรับผิดชอบจะต้องมีกระบวนการจัดการเรียง index ใหม่เป็นระบะ(Rebuild/Reindex)

    4.ไม่ได้ช่วยอะไรหาก column มีจำนวนน้อย(Low Cardinality)
        - ถ้า column ที่ทำ index ไม่ได้มีความหลากหลายของข้อมูลมากนักการทำ index ก็ไม่ได้ช่วยอะไรเช่น Gender, Status ตัวอย่างพวกนี้ไม่จำเป็นต้องทำ index เลยเพราะเมื่อไปอ่าน index แล้วก็ต้องวนมาอ่าน table เกือบทั้งหมดอยู่ดี
