## Response Section

เปรียบเทียบความแตกต่าง

รูปแบบข้อมูล
    Json: Text base อ่านด้วตาเนื้อได้
    Protobuf: เป็น Binary format ต้องใช้เครื่องมือช่วยอ่าน

ขนาดไฟล์
    Json: ใหญ่(เพราะมี format ของมันเช่น key ปีกกา วงเล็บ)
    Protobuf: เล็กกว่ามากเนื่องจากตัดชื่อfield, วงเล็บ ออกเหลือแค่รหัสตัวเลขกับตัวข้อมูล

ความเร็ว
    Json: ช้ากว่า เพราะต้องแปลงข้อความเป็น Object
    Protobuf: เร็วมาก เพราะคอมสามารถถอดรหัสจาก binary ได้โดยตรง

โครงสร้างข้อมูล
    Json: ยืดหยุ่นกว่ามากสามารถปรับเปลี่ยนได้ง่าย
    Protobuf: ไม่ยืดหยุ่นเพราะต้องเขียน .proto เป็นข้อกำหนดโครงสร้าง

การนำไปใช้
    Json: ใช้กับ Web API, REST API, Front-to-back
    Protobuf: ใช้กับ gRPC, Microservices, Inter-service communication


๋JSON 
    ข้อดี 
        1.อ่านง่าย(Human Readable): นักพัฒนาสามารถอ่านและทำความเข้าใจได้ด้วยตาเนื้อ
        2.ความยืดหยุ่นสูง(Dynamic): ไม่จำเป็นต้องมีโครงสร้างอยากจะเพิ่มอะไรเข้าไปก็เพิ่มได้เลย
        3.เป็นมาตรฐานสากล(Universal Support): ภาษาโปรแกรมส่วนใหญ่สามารถอ่าน JSON ไฟล์ได้เลยไม่ต้องลงอะไรเพิ่ม

    ข้อเสีย
        1.ขนาดใหญ่เกินความจำเป็น(Verbose): JSON จะส่งข้อมูลแต่ละครั้งจะต้องมี Key แนบไปด้วยเสมอทำให้เปลื่อง Bandwidth เวลาส่ง
        2.ประมวลผลช้า(Slow Parsing): การแปลงจากตัวอักษรไปเป็นตัวเลขหรือ Object(Parsing) กินแรงของ CPU มากว่าการหาจาก เลขฐานสองตรงๆ
        3.เสี่ยงต่อข้อผิดพลาด(No Strict Typing): เนื่องจากไม่มี Schema คุมฝั่งส่งอาจจะเผลอส่งตัวเลขไปเป็น String ทำให้ฝั่งรับอาจจะพักได้เนื่องจากการอ่านประเภาทของข้อมูลไม่ต้องกัน

Protocol Buffers (Protobuf)
    ข้อดี
        1.ขนาดเล็ก(Highly Compact): เนื่องจากตัดชื่อ field, วงเล็บ และช่องว่างออก เหลือแค่ข้อมูลที่ต้องส่งอย่างเดี่ยวและรหัสประจำ field ทำให้ขนาดของไฟล์เล็กกว่า JSON มาก
        2.ความเร็วในการประมวลผลสูง(Extrmely Fast Parsing): คอมอ่านเล่ยฐาน 2(Binary) ได้เป็นปกติอยู่แล้วการ decode จึงใช้เวลาหน่อยกว่า
        3.ปลอดภัย(Strict Schema & Type Safety): บังคับให้ต้องมีไฟล์ .proto ทั้งฝั่งรับและส่งทำให้ถึงจะมีการดักเอาข้อมูลระหว่างส่งไปทำอะไรก็อ่านไม่เข้าใจอยู่ดี
        4.รองรับการทำงานข้ามภาษาได้(Code Generation): เราสามารถเขียนไฟล์ .proto แค่ครั้งเดี่ยวแล้วสั้งให้โปรแกรม gen code ออกมาเป็น class ของภาษาอื่นๆได้ เช่น Python, Java, Go, C++ เพื่อเอาไปใช้ในฝั่งระบบที่ใช้ภาษาอื่นได้ทันที
    
    ข้อเสีย
        1.มนุษย์อ่านไม่ออก(Not Human Readable): ข้อมูลที่ส่งผ่าน network จะเป็น binary อ่านด้วยตาเนื้อไม่ได้
        2.ขาดความยืดหยุ่น(Lack of Flexibility): ทุกครั้งที่มีการแก้, เพิ่ม, ลดข้อมูลจะต้องแก้ไฟล์ .proto และ gen code ใหม่ทำให้ปรับเปลี่ยนระบบได้ช้ากว่า JSON
        3.ขั้นตอนการทำงานซับซ้อน(Development Overhead): จะมีขั้นตอนเพิ่มขึ้นมาเช่น ต้องดีไซน์โครงสร้าง, ต้องติดตั้ง protoc
